# 向きの第一級化と同点証拠階層 (2026-07-28)

京都市交通局レビュー (docs/verification/kyoto_review.md) の G1 (family 対応の
タイ潰れ) と G3 (循環線の表示分割の不統一) の設計。両者は独立の不具合に
見えるが、**「向き (orientation) が第一級の識別子になっていない」という
1つの構造的欠落の2つの症状**である。本書はその欠落を埋める一般規則を定義
する。G1 (同点証拠階層) は本書に基づき実装済み、G3 (循環表示の分割統一) は
同じ判定器を使う後続として設計のみ記す。

## 1. 対応問題の目的関数 (これまで暗黙だったものの明文化)

family の世代間対応 (M9) が解いているのは「新しい路線網を、旧路線網からの
最少の操作 (継続・改称・統合・分割・新設・廃止) で説明する」ことである。
説明台帳 (最重要設計原則1) の路線版であり、目的は辞書式に:

1. **証拠整合**: 類似度の劣る対応を選ばない。受理閾値未満の辺は使わず、
   confidence 最大を常に優先する (既存挙動、不変)
2. **説明の最大化**: 証拠が完全同点の範囲でのみ、「新設」「廃止」という
   未説明イベントを減らす選択を採る (オッカムの剃刀。内容同一の新 family が
   偶然出現したという説明されない偶然を残さない)
3. **決定性**: それでも残る不定は決定的な順序で閉じる (ルールベースの方針)

貪欲アルゴリズム (best-match) はこの目的関数の近似実装である。厳密な
組合せ最適化はしない — 予測可能性を優先し、目的関数は「近似の対象」として
ここに明示するに留める。

## 2. 同点 (タイ) の意味 — 測度の商

family 類似度の主測度は「翻訳済み停留所**集合**の Jaccard」である。集合は
方向を潰すため、**往路と復路は測度上区別できない** (類似度 1.0 の同点)。
これは雑音ではなく測度の商空間の現れであり、次の一般類型で系統的に発生する:

- **連続運行対 (ラケット)**: 1つの運行が方向別に2 route として書かれる
  (京都 西2/西4、西3/特西4、20系 — route_long_name に「◯◯Ｄ復路→△△Ｄ往路」
  と明記される)
- **循環の方向分割**: 右回り/左回りが別 route (京都 201〜208 ほか)

従来のタイブレークは2箇所 (段階1間引き・ページ割付) とも「新 family 名の
辞書順」で、**同じ新 family の再利用を許した**。その結果、旧2 family が
同一の新 family に吸われ、もう片方の新 family が「新設」に落ちる
(京都 G1。特西5/西6 が無事だったのは辞書順の偶然)。

## 3. 一般規則: 同点証拠階層 (tie-break comparator の一元化)

**confidence が完全同点の候補間の優先順**を、次の単一の比較器で定める。
原理は「構造的選好で埋める前に、まだ使っていない証拠を使い切る」:

| 層 | 比較 | 原理 |
|---|---|---|
| 1 | (前提) confidence 最大のみが候補 | 証拠整合 — 同点でないものに比較器は触れない |
| 2 | **向きの一致度**: 代表停車列同士の順序一致率が高い方 | 集合測度が潰した方向情報を系列から回復する。往路↔往路が往路↔復路に勝つ |
| 3 | **名称類似**: 新旧 family 名の類似比が高い方 | 「名前は弱い事前」(M9) — 内容が語れないときだけ発言権を持つ。系統番号入替のような改正で交差改称 (西3→特西4 と誤対応) を防ぐ |
| 4 | **未使用優先**: まだ対応先に選ばれていない新 family | 説明の最大化 (目的関数第2項) |
| 5 | 新 family 名の辞書順 | 決定性の確保のみ |

適用箇所は「アルゴリズムが同点辺から1本を選ぶすべての場所」であり、
現時点では:

- `classify_family_components` の段階1間引き (route_family.py) —
  各旧 family の最良エッジ選択
- `page_family_maps` (builder.py) — 旧 family のページ割付

2箇所が独立に恣意的なタイブレークを持っていたことが欠陥の本体なので、
**比較器を1つ定義して共有する** (UQ トラックで表示整形関数を一元化したのと
同型の対処)。停留所クラスタ翻訳 (`build_stop_translation`) にも同形の
辞書順タイブレークがあるが、停留所に向きの概念がなく実害の観測もないため
対象外 (将来、名称類似層のみ適用する余地はある)。

### 3.1 向きの一致度の定義

family の代表停車列 (最長パターンの基底名列、同長は辞書順で決定的に選ぶ)
同士で、共通停留所の**相対順序の一致率** (一致ペア数 ÷ 共通ペア総数) を取る。
同方向 ≈ 1.0、逆方向 ≈ 0.0。共通停留所が2未満なら中立 (0.5)。
方向グループ判定 (presentation の order agreement) と同じ意味論だが、
層の依存方向 (identity は report に依存できない) のため identity 側に
純関数として実装する。

### 3.2 何をしないか

- **主測度の置換はしない**: 集合 Jaccard の粗さは停留所の挿入・削除・部分
  改廃への頑健性 (朝日町の全面改称を通した実績) の裏返し。細かい証拠は
  同点のときだけ聞く — 頑健な粗い測度 + 精密なタイブレークの分業
- **1:1 最適割当はしない**: N:M の意味論 (統合・分割は正当 — 朝日町の
  21→9 は多:1 が正解) を壊す。当初案として検討し撤回 (kyoto_review.md G1)
- **厳密最適化はしない**: §1 のとおり

## 4. 影響範囲と回帰基準 (2026-07-28 実測)

比較器は confidence 完全同点のときしか挙動を変えないため、影響は同点を
含む成分に限定される。事前調査 (scripts/survey_family_ties.py):

| ペア | 同点タイの旧 family | 期待される変化 |
|---|---|---|
| 朝日町 (21→9 統合、間引きの発祥事例) | 0 | **完全不変** (MERGED 2成分は非同点) |
| 名古屋 (同名改称基準) | 0 | **完全不変** |
| 桑名・永井・根室ほか | (実装時に確認) | 不変 |
| 京都 | 2 (割付) + 間引き内 | 20系のページ割付正常化、西系の 2:1 潰れ解消 |

併せて表示不変条件を追加する: **「新設ページ ∧ (旧名称あり ∨ 類似度1.0の
候補あり)」は矛盾** — presentation.self_check に採録し検証モードで可視化
(廃止側も対称に)。対応の取りこぼしの恒常的な煙感知器になる。

## 5. G3 への展開 (2026-07-28 実装済み — presentation.md PI-7)

循環線では ①地図 (leg)・③時間帯別本数 (system 行)・④時刻表 (sheet) が
それぞれ別の分割を出し、しかも ③ の行ラベルは起終点生成のため循環では
「九条車庫前→九条車庫前」×2 と識別不能になる (kyoto_review.md G3)。

一般規則 (表示不変条件 PI-7): **循環線は「回り」を第一分割とし、
①③④と地図が同じ分割を共有する。ラベルは起点→終点でなく「◯◯先回り」**。
回りの判定は §3.1 の順序一致率そのもの (逆回りは一致率 ≈ 0) であり、
G1 で実装した判定器を presentation 層から再利用する。

実装 (2026-07-28): 正体は `_direction_groups` の**例外の撤廃** — 起点=終点の
路線だけ順序一致率を問わず forward に畳んでいた分岐を消し、双方向と同一の
判定器・同一の閾値 (reversed_max) に統一した。向きの表示名は分冊と同じ
「先回り」命名器 (起終点は候補から除外)。③の leg 行・④のバケット・地図の
線と凡例は元から `s["leg"]` / `leg_labels` に従う汎用実装だったため自動追従。
形のスペクトラム: 完全循環は2つの向きに分かれ、片回りのみ・Q字 (幹線支配で
一致率が閾値超) は1つの向きのまま (= 従来表示、退化保証)。小さすぎる輪は
パターン類似度の段階で1クラスタに束なり分割対象にならない (正当)。
検証: 京都 205/206/208/北8 が2つの回りに分割 (206 の5分冊・重複ラベルも解消)、
106 (片回り) 不変、桑名 陽だまりの丘線も正しく分割。立川・しんぐう・根室は
presentation ハッシュ不変。
