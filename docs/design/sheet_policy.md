# 時刻表の分冊 (sheet) ポリシー — 基準の一本化

2026-07-30。掛川大須賀線のレビュー (上りは1枚、下りは5枚に分冊) を発端とする
分冊ポリシーの総合レビューと改訂の設計記録。実装は presentation.py の
`group_sheets` と分冊トリガー部、閾値は config [presentation]。

関連: docs/design/presentation.md R17 (分冊の導入、2026-07-08 徳島バスレビュー)、
調査スクリプト scripts/survey_sheet_policy.py、調査結果 data/sheet_survey/。

## 1. 問題 — 基準が2つあり、調停されていなかった

R17 改 (改訂前) の分冊決定は2段階で、それぞれ別の閾値を持っていた:

1. **トリガー**: 1枚で作った表の「飛び (経由行の途切れ) ラン数 / 時刻列数」
   (avg_gap) が 1.5 を超えたら分冊する。= 「1.5 までは読める」という可読性定義。
2. **併合**: 分冊時はパターン単位にばらし、「併合したときの飛び増加量/便」が
   0.5 以下の対だけを貪欲に束ねる。= 「0.5 までしか併合しない」という別の基準。

分割が発動した瞬間に基準が3倍厳しくなるため、トリガー付近 (avg_gap 1.5〜2.0)
で枚数が不連続にジャンプする「崖」があった。

**掛川大須賀線 (prev_2→current) が崖の実例**: 上り 7便4パターン avg 1.29 →
1枚。下り 7便6パターン avg 1.86 → 5枚。複雑さはほぼ同じなのに、閾値を挟んで
紙一重で 1枚 vs 5枚 になった。しかも下りは max_cost 1.0 相当まで併合すれば
2枚 (avg 0.00 / 1.40) で、**どちらもトリガー自身の可読性定義 (≤1.5) を満たす**
— 現行の5枚は自分の基準に照らしても過剰だった。

可読性定義 1.5 より3倍厳しいことの直接の帰結。1便だけの分冊 (1列の「時刻表」)
も多発し、分冊ラベルの質も落ちる (「先回り（2）」等)。

### 逆方向の欠陥 (改訂実装後の検証で発見、2026-07-30)

旧規則には**過小分割**もあった: 併合可否が「飛びの増加量/便 ≤ 0.5」という
規模依存の量だったため、便数の多い群同士は分母が大きく、**基準超のままでも
0.5 を潜って1枚に戻ってしまう**。京都 市バス80 (35列 avg 2.0)・名古屋 新瑞14
(avg 3.2) 等、約20バケットがトリガー超なのに1枚で表示されていた。
つまり旧規則は小さいバケットで砕きすぎ、大きいバケットで束ねすぎという
両方向の崖を持っていた — どちらも二重基準と規模依存正規化の帰結。

## 2. 原理 — 可読性の定義は1つ、その範囲で枚数最少

> **分冊は、1枚では可読性基準を満たせないときに限り行い、
> 全分冊が基準を満たす範囲で枚数を最少にする。**

可読性基準は従来と同じ avg_gap ≤ θ (θ = 1.5、config)。併合専用の第2閾値は
廃止する。この原理の妥当性 (データへの適合ではなく構造からの根拠):

1. **連続性**: 複雑さが単調に増えると枚数も 1→2→3… と小刻みに増える。
   閾値ぎわの微差で 1枚⇄5枚 が跳ばない。差分ツールとしては世代間の安定にも
   直結する (分冊は新旧合成で決まるため、崖があるとダイヤ微修正で次回比較の
   見た目が急変する)。
2. **説明可能性**: 「なぜこの枚数か」に「1枚では基準超。これ以上束ねると
   どれかの分冊が基準を超えるから」という一文で答えられる。二重基準では
   この説明が書けない (0.5 の根拠を 1.5 と独立に説明できない)。
3. **情報の集約性**: 読める範囲で枚数最少 = 1枚あたりの列数最大。
   「この向きは1日何本か」が最少の視線移動で掴める。1便分冊の抑制は
   独立ルールではなくこの原理の系として得られる (併合しても基準内なら
   必ず併合されるため)。
4. **見かけの整合は強制せず、導出する**: 上下・曜日・世代間で同一の単一基準を
   独立に適用する。実態が違えば枚数は違ってよい (掛川は上り1枚・下り2枚になる
   — 下りにだけ先回り変種があるのは事実)。「複雑さが近ければ枚数も近い」が
   基準の連続性から保証されることが本質で、対称性の強制は方向ごとに実態が
   違う路線で嘘になるため行わない。

## 3. 仕様

バケット (方向グループ × 向き × 曜日) ごとに:

1. **トップダウン第1段 (不変)**: まず1枚で作り、avg_gap ≤ θ ならそのまま1枚。
   「読める表は分冊しない」の R17 原則は維持 — 全バケットの97%はここで確定し、
   出力は改訂前とバイト同一。
2. **束ね直し (改訂)**: 超えたら一意な停車パターン単位にばらし、貪欲併合:
   - 併合候補 = 全ペアのうち **併合後の表が基準内 (avg_gap ≤ θ) に収まるもの**。
   - その中から「飛びの増加量/便」最小の対を併合する (最も自然な対から束ねる
     — 包含 (区間便) は増加 0 で最優先、経由がほぼ重なる対がそれに続く)。
     同点は探索順 (パターンのソート順) で決定的。
   - 併合候補がなくなったら終了。残った群が分冊。
   - **no-harm 併合 (実行不能領域の扱い)**: 経路変更対 (新旧で停車列が違う
     便対) は旧列・新列を同じ軸に並べるため**列の内部に飛びを持ち**、
     どう分割しても基準内に収められないバケットがある。そこでは基準の制約が
     空振りし、貪欲が止まった位置で恣意的に砕ける (市バス80 が [34便+1便] の
     無意味な2枚になる等)。このため併合可否に第2節を追加する:
     **両群とも基準超のときに限り、併合後の avg が両者の最大以下 (悪化しない)
     なら併合してよい** — 分けても読みやすくならない群を無意味に砕かない。
     片側だけ基準超の対は併合後が基準内に収まる場合しか併合されないので、
     **基準内の分冊が基準超の群に汚染されることはない**。新しい閾値は
     導入しない (使うのは θ と「両者の最大」のみ)。
3. ラベル (識別停留所「A・B経由」/「◯◯先回り」)・並び順・③の leg 行との
   便数一致は不変。

- 厳密な最少枚数 (集合分割の最適化) は解かない。貪欲での近似とする —
  決定性と説明可能性 (「この対は束ねると基準を超える」) を優先し、
  最適化は計測で問題が出てから (CLAUDE.md 原則5)。
- θ は従来のトリガー値 1.5 を据え置く。R17 導入時のレビュー (徳島で読めなかった
  表と芦屋・臨港の読める表の分別) で校正された値であり、今回の調査でも
  適正分冊の per-sheet avg は 0.9〜1.4、要分冊の全載せは 1.6〜4.2 に分布し
  分別面として機能している。今回のデータに合わせた再調整はしない。

### config

```toml
[presentation]
# 時刻表の可読性基準: 「飛び (経由行の途切れ) ラン数 / 時刻列数」の上限。
# 1枚で基準内ならそのまま。超えたら、全分冊が基準内に収まる範囲で
# 枚数最少になるようパターンを束ね直す (sheet_policy.md)
sheet_max_gap_per_trip = 1.5
```

`sheet_split_trigger_gap_per_trip` (1.5) と `sheet_merge_max_gap_per_trip`
(0.5) は廃止し、単一キーに置き換える。値の実質変更はトリガー側にはない
(1.5 のまま)。

## 4. 棄却した代替案

- **注記方式** (1枚に全便を載せ、経由差は列頭の記号+凡例に落とす。軸は背骨に
  絞る): 低頻度で全便が固有経路の路線 (おでかけ北設型、8便8パターン) では
  紙の時刻表の慣行に近く読みやすい可能性があるが、**不採用** (2026-07-30
  ユーザー判断)。理由: 適用条件が特定のデータ型に限られ、分割方式との
  二本立てになって表示の一貫性が崩れる。変種停留所の時刻が表から落ちて
  網羅性 (どの停留所の時刻もどこかの表にある) を保ちにくい。北設型にも
  一本化した基準による分冊 (5枚→2〜3枚) を適用する。
- **上下・曜日間の対称性の強制** (同一ページ内で分割粒度を揃える): 方向ごとに
  経由変種の実態が違う路線 (掛川下りのみ先回り変種) で嘘の対称になる。
  §2-4 のとおり、整合は単一基準の帰結として得る。
- **幅 (列数) を可読性基準に加える**: 画面は横スクロールで幅を吸収できるが、
  飛びだらけの表は何をしても読めない。飛びのみを基準とする現行の物差しを維持。
- **最小分冊便数 (1便分冊の禁止) の独立ルール**: 原理の系として大半が解消
  されるため独立ルールは置かない (真に孤立した経路変種が1便分冊で残るのは
  正当 — 束ねると基準を超えるという説明が立つ)。

## 5. 回帰の錨 (事例セット) と DoD

改訂の検証は以下の性格の違う事例で行う。「枚数が変わらないこと」ではなく
**「全分冊が基準内 + これ以上束ねると基準超」の状態が保たれ、変化した箇所は
目視で妥当**、を合格条件とする:

1. **紙一重の非対称**: 掛川大須賀線 — 下り 5枚→2枚 (期待)、上り 1枚不変。
2. **分冊が正しく必要**: 徳島 川内循環線・立道線、京都の循環左右回り 16件 —
   併合すると基準を超えることを確認 (枚数維持が期待値)。
3. **過剰分割の典型**: 徳島 北泊線 (4バケット)、おいでん 豊田・渋谷線 (3タブ)。
4. **真に複雑**: 北泊 → 鳴門駅前 平日 (最少でも4枚相当) — 大きく減らないこと。
5. **分冊ゼロの健全例**: 沿岸バス・豊田市地域バス (92/93)・芦屋・臨港 —
   分冊ゼロのバケットは出力バイト不変。
6. **極端断片化**: 北設 豊根東栄線 (8便8パターン)・坂宇場線 (3便→1便×3枚) —
   一本化基準での併合結果を目視確認。

DoD: 合成テスト (既存3件 + 崖の解消を固定する新規)、10フィード before/after で
非分冊バケットの不変と錨事例の確認、presentation.md R17 改訂2 の記録、
config キー移行、本文書への検証結果追記。
