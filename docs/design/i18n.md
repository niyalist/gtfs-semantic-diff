## 0.5 言語方針 (2026-09-14 確定)

- 対応言語は当面 **en + ja**。第3の言語の追加を妨げない —
  「辞書を1つ足す以外の変更が要らない」を構造要件とする。
- 日本語環境からのアクセスは日本語 (英語がメインの座でも構わない)。
  **非日本語環境には英語を見せ、日本語は原則現れない** — 「en モードの出力に
  フィード由来データ以外の日本語が残らない」を完成の定義とし、CJK 文字の
  機械監査 (`[ぁ-んァ-ヶ一-龥]` 検索 + データ項目の許容リスト) を CI に置く。
- **ja 出力は不変**: i18n 化のリファクタで日本語出力が変わらないことを機械検査
  (digest はバイト同一、viewer は PI + vitest — P トラックの出力不変と同じ手法)。
- **公開 URL は不変・追加のみ**: 既存 `.digest.md` 等は ja のまま、en は新規
  成果物として併設 (§I6)。**英語環境からのアクセスが日本語を挟まず英語に辿り
  着ける導線** (HTML の link rel=alternate、llms.txt、developers ページ) を条件に
  「併設」で確定 — 正の言語の切替は行わない。
- MCP は **instructions・ツール説明を en に一本化** (LLM の共通語。日本語利用者の
  エージェントも en 説明を問題なく扱う)。**本文を返すツールは `lang` 引数**
  ("en"/"ja"、既定 en) で選択制 — 日本語の会話が数値・固有名詞を日本語のまま
  正確に引用できるようにする。
- terms の英語版は**参考訳** (日本語正文が優先) と注記する — 東大伊藤研の運用で
  この位置付けとする。
- **記号の扱い** (2026-09-15 確認): → ⇄ ▲▼ ‖ ＊ 「・・」等の言語共通
  記号は両言語で不変とし、CJK 監査の対象外。en で置き換えるのは
  (a) 漢字を含む札 (【新】【廃】→ [new]/[cut] — 列ヘッダの ＋new/−removed
  と同語彙)、(b) 文として読まれる CJK 句読点 (・区切り、〜) のみ。
- 開発文書 (docs/design、docs/spec、検証ログ) は日本語のまま。

### I2: Web/UI の英語対応 (G1/G2/G3/G7)

- 入力 UI: ja/en 辞書 + 言語トグル (ビューアと同じ流儀)。**初期言語は
  navigator.language** (ja 系以外は en)。英語時は zip アップロードを前面に、
  **gtfs-data.jp ピッカーは控えめに** ("Feeds from gtfs-data.jp (Japan)" として
  折り畳み等)。単一 HTML 内切替で URL は増やさない。
- 【改訂】**ログイン後 UI (マイページ・履歴・zip 保存・削除) も含める**。
- API エラー: 列挙可能なものは**エラーコード** (`same_generation` 等) +
  クライアント辞書。動的な入力不備メッセージ (ファイル・行番号入り、
  GtfsLoadError 系) はコード化になじまないため **`error` (ja) + `error_en` 併記**
  とし、フロントが言語設定で選ぶ (error_kind は言語非依存で既存)。
- 利用規約: 同一ページ内切替で en 版 (**参考訳・日本語正文優先の注記付き**)。
- OGP/メタ・og:locale もここで。admin ページは対象外 (運用者向け)。
- **DoD**: 英語設定のブラウザで「トップ→アップロード比較→レポート閲覧→
  ログイン→マイページ→削除」が全て英語で完結する (実操作確認+スクリーンショット、
  CJK 監査ゼロ)。

## 2. 決めごと・前提

- 翻訳は「ja/en 辞書の対管理 + ずれゼロをテストで担保」の現行方式を全面に広げる
  (ビューアで実績あり)。翻訳ファイルの外部化 (gettext 等) は規模に対して過剰。
- gtfs-data.jp 連携は日本専用のまま (国際の入口は zip アップロード。
  Mobility Database の世代 API 連携は将来構想 — スコープ外)。
- レポート本文の「事実」(名称・数値) はフィード由来のまま (翻訳しない)。
  翻訳するのは UI ラベル・説明文のみ。
- 国際フィードの検証は「ルールベースの機械処理で出来ることをやる」原則のまま
  行う — 各国固有事情への過剰適応はしない。

## 4. 恒常開発ルール (I トラック完了後も全開発に適用、2026-09-16 制定)

I2〜I6 の実装・実地レビューで確立した規律。**新機能・修正はすべて以下を
満たすこと** (CLAUDE.md 開発ルールから参照)。

### 4.1 文字列の置き場所

- **UI に出る文字列をコードにハードコードしない**。viewer は i18n.js の
  ja/en 辞書 (キー一致は自動検査)、入力 UI は index.html の辞書
  (`// en-dict-begin` マーカー内)、静的ページは lang ブロック
  (`<!-- en:begin -->`)。**監査 (test_web_i18n / en_audit) が見張れる場所**
  以外に UI 文字列を置かない — 監査対象外の文字列は今回の title 漏れの
  ように人間レビュー頼みになる。
- Python が生成する表示用文字列は (a) ja 文字列 + 構造化 parts の併記
  (label_parts 方式 — viewer が en を組み立てる) か、(b) lang 引数での
  両言語生成 (digest 方式) のどちらか。**ja の文を bundle に単独で焼き込む
  ことは新規にはしない**。
- データ由来の文字列 (停留所名・路線名・trip_id 等) は翻訳しない。
  事実は元データのまま、翻訳するのは当方のラベル・説明文のみ。

### 4.2 言語の決め方・不変条件

- 言語判定は「localStorage "lang" (全ページ共有) > navigator.language
  (ja 系→ja、他→en)」。ページ・成果物ごとに独自の判定を作らない。
- **ja 出力の不変は機械検査**: 辞書化・parts 化のリファクタで日本語の
  表示文字列を1文字も変えない (partsLabel の ja 恒等 vitest、digest の
  ja レンダ一致テスト、PI)。変えるときは通常の表示変更 DoD
  (presentation.md) を踏む。
- **公開 URL は不変・追加のみ**: 既存 ja 成果物の URL・バイト列に触れず、
  en は新成果物として併設する。digest の見出しは両言語とも契約
  (変更は docs/api/reference の更新とセット)。
- 第3言語の追加は「辞書・カタログに1言語ぶん足す」以外の変更を
  要しない構造を保つ。

### 4.3 面ごとの言語ポリシー

- **人間向け UI** (Web・viewer・digest .md): ja/en 両対応、既定は環境。
- **機械向けインタフェース** (MCP instructions/ツール説明/応答ノート・
  llms.txt・robots.txt・エラーコード): **en 一本**。本文を返すツールは
  lang 引数 (既定 en)。
- **API エラー**: 列挙可能なものはコード、動的な文は `error` (ja) +
  `error_en` 併記 + `error_kind`。
- **JSON 成果物**: 言語中立 (name_ja/name_en 両持ち)。言語別の JSON 複製は
  作らない。
- **開発文書** (docs/design・docs/spec・検証ログ): 日本語。
  **外部向け文書** (README・docs/api): en 正 + ja 併設 (*.ja.md)。

### 4.4 記号・ロケール表記

- 言語共通記号 (→ ⇄ ▲▼ ‖ ＊ 「・・」等) は両言語で不変・監査対象外。
  en で置換するのは漢字を含む札 (【新】→[new]) と、文として読まれる
  CJK 句読点 (・区切り→ " · "/", "、〜→ –) のみ (§0.5)。
- 通貨・単位はデータから取る (円決め打ちの類を新設しない)。時刻は GTFS の
  現地時刻をそのまま表示し、タイムゾーン変換をしない。
- 日本固有の機能 (gtfs-data.jp 連携等) は en では控えめに出す。
  無効化はしない。

### 4.5 Svelte 実装の注意 (実地レビューで踏んだ罠)

- `tt`/`$lang` を**関数の中だけ**で参照する値は言語切替に追従しない
  (マークアップの依存に載らない)。App の `{#key $lang}` 再マウントが
  最終防衛線だが、新規コードはマークアップから `tt(...)` を直接参照する
  形を基本にする。
- `<input type="file">` 等ブラウザ描画のネイティブ部品の文言はページの
  言語に従わない (ブラウザ UI 言語)。仕様として許容する (置き換えない)。

### 4.6 検証 (新機能の DoD への組み込み)

- 表示面を追加・変更したら: (a) 辞書キー一致 (自動)、(b) en CJK 監査に
  載ること (en_audit のフィクスチャが踏む経路か確認、必要なら
  scripts/gen_i18n_en_fixture.py を拡張)、(c) ja 不変の該当テスト。
- 監査の原理は「**英語データのフィードで CJK が出たら当方の焼き込み**」。
  この前提を壊す (フィクスチャに日本語データを混ぜる等) 変更をしない。
