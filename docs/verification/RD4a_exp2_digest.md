2026-07-30。RD4a (AI 向け digest) の残 DoD —
「EXP2 (docs/verification/EXP2_announcements.md、公式告知との突合 12フィード
68項目) の判定が、HTML レポートを開かず **digest (L0+L1) だけで**再現できるか」
の検証記録。

## 方法

- EXP2 と同一の12ペアを取得し (scripts/exp2_digests.py、ペアは改正日を跨ぐ
  世代を API から解決 — data/exp2/manifest.json)、L0 digest (md+json) を生成。
- 各項目について、シートの軸1判定 (◎/○/×) と同じ結論に digest のみで
  到達できるかを判定した。L1 (`--digest-route`) は YUKI 北部東・絹川の
  2回使用。events.json / rawdiffs.json (L2)・HTML は一切開いていない。
- CHI・NAGAI はシートと同一ペアのローカル zip (地鉄 2025-10-16→2026-04-01、
  永井 2025-04-01→2025-10-01)。

または HTML が必要なもの。判定が**逆転** (シートで検出のものが digest で

## 部分再現 6件の性質

いずれも「検出の有無」は digest で判定でき、足りないのは**深掘りの根拠**:

1. **量的内訳** (TSU-03 割引運賃、CHI-04 時間帯): FARE_CHANGED /
   SERVICE_REDUCED の件数は §3 にあるが、fare_attributes の内訳・時間帯の
   帰属は quantification (L2) にしかない。設計どおりの層分担 (digest は
   要約、深掘りは events.json) であり、レシピ (docs/api/README.md) の
   「深掘りが要るときだけ L2」で回収される。
2. **表示の意味づけ** (TAKAOKA-02 の「回り」、YUKI-06 の接続先): G3 の
   向き表示・④の停車列は視覚表現であり、digest の守備範囲外とした設計判断
   (ai_interface.md §7) の帰結。
3. **経由化の個別停留所名** (YUKI-02 曽我殿台、NAKA-04): B群イベントの
   件数は §3 にあるが対象停留所名は L2。

## 検証で見つけた digest 側の問題と対処

- **§4 停留所リストが無制限** — SUWA (新設96+廃止165)・TSU (廃止160) で
  §5 が埋もれる。→ `digest_stops_max` (config、既定50) で種別毎に切り、
  超過を件数+JSON 誘導で明示 (省略の明示原則)。test_digest に追加。
- **便数同数の全便入れ替えが L0 で無言** — YUKI 北部東 (旧3+新3便で総数
  不変・全便入れ替え) は L0 では変化ページとして載るが変化タグが出ない
  (page digest の語彙は presentation と共通で、便数不変+rerouted 0 のため)。
  L1 を見れば 廃止3+新設3 と経由ラベルの違いが読める。**改善候補** (L0 の
  changes に added/removed 便数を足す案) として記録 — presentation の
  一言ダイジェスト (R19) と語彙を共有しているため、変えるなら人間向けと
  同時に変える (数値一致不変条件)。

## 結論

RD4a の DoD を満たす: 判定の逆転ゼロ・91% 完全再現・部分再現はすべて
設計どおりの層分担に帰着する。digest は EXP2 型の突合作業 (ユースケース (b))
の一次資料として使える。生成物: data/exp2/*.digest.md|json (gitignore 済み)。
