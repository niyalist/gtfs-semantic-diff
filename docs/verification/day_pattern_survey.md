# 運行日パターン調査 — SD5/SD6 (運行日世界・レジーム整列) 検討用データセット (2026-07-25)

目的: PRT の特定日合算誤り・bus-vision 世代同居の再発見 (2026-07-25 振り返り) を
一般解 (原則A「同じ日に走らないものを足さない」/ 原則B「レジーム切替点で整列」)
に落とす前に、世の中の運行日表現パターンを広く観測し、設計の当たり判定を行う。

手段: `scripts/survey_day_patterns.py` — calendar / calendar_dates / feed_info
だけを読む軽量分類器。タグ:

| タグ | 意味 | 設計上の論点 |
|---|---|---|
| dow_odd | 変則曜日フラグ (月水金等、標準6種以外) | dow_* 一級化 (M10) の適用範囲 |
| mixed_expiry | service 毎に有効期限がバラバラ (寄せ集め) | 窓・レジームの定義が service 単位で割れる |
| cd_only | calendar なし・calendar_dates のみ | 実効運行日集合が唯一の真実 (規則が無い) |
| holiday_cd | cd_only かつ追加 1〜5 日 (祝日専用の素朴型) | 原則A: 互いに素な特定日世界 |
| holiday_flagged | フラグあり + 削除希釈で実効 ≤5 日 (PRT 型) | 同上 (SD1 密度判定の対象) |
| seasonal_split | 同一フラグの期間分割 (STM 型 / **世代同居も構造上同型**) | 原則B: レジームか季節か同居かの判別 |
| swap_dates | 同日に運休+代替 (日本の祝日振替standard) | 現行の「日曜ダイヤで運行」説明の裏付け |
| school_kw | service_id に 学/校/休業等 (学校日ダイヤ) | 平日の下位分割 (ラベル語彙への挑戦) |

### 新たに観測した類型 (当初の仮説になかったもの)

- **月例運行**: 毎月第N水曜のみ運行 (中津市 東谷線/西谷線/屋形線 —
  service が月ごとに分かれ、期限も月ごと = mixed_expiry と複合)
- **施設連動**: 美術館の開館/休館とダイヤ連動 (甲賀市「ミホ開館/休館」、
  直島「ベネッセ 18時閉館シャトル」)
- **祭り期間**: 新庄まつり期間 service (フラグ+削除希釈の PRT 型で表現)
- **特定日増便**: 「20260809_16_23増便」(津エアポートライン) — 花火大会等の
  1日限り増便が cd_only service で載る
- **実効0日 service**: 冬期ダイヤが期間外で実効 0 日 (米沢市営 —
  SD1 の inactive 分類が正しく効く事例)

## プロトタイプ検証 (2026-07-25、scripts/validate_day_worlds.py)

原則A (day_type ラベル × 実効日重なり成分 = 運行日世界) + 内容ダイジェスト
(trip 署名多重集合の hash) による束ね・世代間対応を、収集済み全事例に適用した。

### 主要な観測

1. **世界分割はレギュラー型にも必要** — 特定日に限らない:
   - STM (四半期): 土曜 = M期 18,002便 / U期 13,789便 の2世界。現行は合算
     31,791便に見える (**四半期分割フィードはレギュラー型でも現行集計が過大**)
   - 桑名 0710 同居: 平日 = A期 557便 / B期 553便 の2世界 (世代同居の正体)
   - しんぐう渡船 (季節): 毎日 = 春夏12便 / 秋冬10便 の2世界
2. **完全一致束ねが無害な分割を自動で透明化する**:
   - 市川三郷: 火木(前)/神明の花火(火木)/火木(後) の3世界 → 内容同一で1パターン
     に復元 (花火日を挟む再掲は見かけの分割だった)
   - 甲賀ミホ: 開館1〜4 と 休館1〜3 が交互 → 開館/休館の2パターンに束なる
     (振動型はレジーム論なしで表現できる)
   - STM 新の SV 3分割 → 1パターン
3. **世代間対応の信号は「内容一致」と「日付一致」の2つで、相補的**:
   - 河内小休校日: 日付が年度でずれても内容ダイジェスト一致 → 対応 ✓
   - しんぐう: 春夏/秋冬パターンが翌年も同ダイジェストで再出現 → 対応 ✓
   - 新庄まつり: 日付 (8/24〜26) は完全一致だが内容が変化 → 日付一致で対応し、
     差分は便対応 v1 が説明する (**ダイジェスト一致だけでは拾えない反例**)
4. **T3 (季節) と世代同居の判別信号 = 「相手世代でのパターン再出現」**:
   - 季節 (しんぐう): 両世界とも新世代に再出現する
   - 同居 (桑名): 旧の先頭世界 (A) は新世代に再出現しない
   - SD2 の後継カバー率ヒューリスティクスより素直なデータ由来の判別になりうる
5. **危険域: 期間の重なりによる世界融合** (データのずさんさをそのまま映す):
   - 中津の冬6ヶ月 service が期間重複で1世界に融合 (7日12便)
   - 甲賀旧の「ミホ休館2」+「ミホ開館3」が重複で融合 (意味の異なる service)
   - 立川旧の 年末+正月 融合 (新世代では分離)
   - 世界は「同じ日に走る」というデータの主張に忠実 — 融合はデータの実態
6. **粒度**: PRT の 7/4 vs 9/7 はフィード全体では内容不一致 (2,865 vs 2,833便 —
   路線により祝日ダイヤが異なる) が route 1 単位では 38/38 一致。
   **束ね・対応は C群と同じ (路線×方向) 粒度で行うべき**。LA Metro の
   irregular 9世界 (路線混在) も同じ結論を支持

### 設計への含意 (service_days v0.8 = SD5/SD6 の骨子)

- SD5 (運行日世界): 世界分割 (全 day_type)・(路線×方向) 粒度の内容ダイジェスト
  束ね (特定日1/2… 表示)・世代間対応は「内容一致 or 日付一致」の2信号 +
  残りは既存便対応 v1 (対応付けブロックはラベル単位のまま = v1 規則不変)
- SD6 (切替の整列): 単調な世界交代 (旧の先頭世界が再出現せず、末尾世界が
  新と対応) を「切替」と判定し、旧初期世界 vs 新最終世界で比較。
  再出現あり (季節・振動) は世界対応のみで説明し切替扱いしない
- 便数の意味を「1日あたり」に統一 — ラベル合算をやめ世界毎に数える
  (レギュラー型1世界のフィードでは従来と同値 = 退化保証)
