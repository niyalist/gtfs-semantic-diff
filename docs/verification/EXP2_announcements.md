# 案A 判定シート: 公式告知とレポートの突合（判定下書き 2026-07-30、2軸化改訂）

**判定は2軸**。システムの「顔」はレポートモードであり、検証モードの数百
イベントの1つに含まれるだけでは「伝わる」とは言えない（レビュー指摘 07-30）。

- **軸1 検出**: ◎一致（対応する表示・粒度も同等）／○部分一致（検出されて
  いるが粒度・意味づけが異なる）／×不検出。×の理由: [データ外]／[語彙]／[同定]
- **軸2 提示**（検出◎○の項目のみ）: レポートモードでの可視性
  - **A 言明**: 見出し・項目として端的に言明される（第1部の項目、第2部の
    停留所リスト、路線ページの新設/廃止見出し・サマリーLev.1〜4・ダイジェスト）
  - **B 表内**: 本数表・時刻表・曜日タブを読めば分かる（Lev.5 の件数集約含む）
  - **C 検証のみ**: レポートには現れず検証モード（第4部・網羅性ビュー）のみ

軸2はバンドル内のプレゼンテーションモデル（coverage.destinations =
イベント→表示先の部、summary.level1〜5、stop_changes、digest）から機械的に
判定した（＝本システムの3層トレーサビリティを評価の測定器として使用）。
※印は HTML 目視での最終確認が望ましい箇所。

**軸2 提示**（検出された60項目）: **A 言明 50／B 表内 10／C 検証のみ 0**。

- **C=0 が重要な結果**: 告知に載るレベルの変化で、検証モードにしか出ない
  （＝レポートで埋もれる）ものは無かった。第4部（その他）に落ちるイベントは
  各フィードに数十件あるが（例: 地鉄98件）、その内訳は経路形状の微変化・
  ID張り替え等であり、告知対象の変化とは重ならない。
- **B の10件が「端的なメッセージ」の改善余地**: 内訳は 時刻改正の総括
  （TAKAOKA-01・NAGAI-05: Lev.5 の件数集約と④でしか読めない）、経由・接続の
  細部（YUKI-01/02/04/06）、曜日変更（YUKI-08: 曜日タブと本数で読めるが
  「曜日が変わった」という言明がない）、期間・季節構成（TSU-05・NAKA-04）、
  運賃内訳（TSU-03）。
- 参考: レポート被覆率（イベント→表示先）は12フィードで 0.71〜1.00。
