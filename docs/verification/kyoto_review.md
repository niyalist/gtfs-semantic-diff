## 1. G1 — family 対応のタイ潰れ: 「新設なのに旧名称/類似度1.0」(指摘 3.1, 3.2, 3.3, 3.12, 3.90)

### 観測

京都の「ラケット」(桂駅⇄JR桂川駅の往復が別系統名で連続運行される対) は、
routes.txt 上こう書かれている:

```
旧: 市バス西３（～特西４） = 西3Ｄ復路号系統（特西4Ｄ往路に連続運行）
    市バス特西４（～西３） = 特西4Ｄ復路号系統（西3Ｄ往路に連続運行）
新: 市バス西３（→特西４）、市バス特西４（→西３） (名称の～が→に変更)
```

family 対応成分の実測:

| 成分 | 結果 |
|---|---|
| 特西4/西3 | old 2 → **new 1** (特西4(→西3) のみ。西3(→特西4) は不対応 → 新設扱い) |
| 西2/西4 | old 2 → **new 1** (同上。西4(→西2) が新設扱い) |
| 特西5/西6 | old 2 → new 2 (**正しく 2:2**) |
| 20 系 | old 2 → new 2 (成分は 2:2 だが、ページ割付は下記のとおり偏る) |

結果の表示 (ページ番号は現行ソート):

- [2] 西3(→特西4): **新設 0→27**、candidates に 特西4（～西3）1.0 / 西3（～特西4）1.0
- [90] 特西4(→西3): 55→28▼、④に「桂駅西口→JR桂川駅前 **27→0**」の全廃シート
  — [2] の「0→27」と対をなす。**同じ27便が片方で全廃・片方で新設に見える**
- [1] 20(菱川→淀): **新設 0→11 なのに旧名称2件が付く** (自己矛盾)。
  ④には旧便が表示される (6→7, 4→4)
- [12] 20(南横大路→淀): 36→15▼、④合計 26→15 (ヘッダと10便乖離)

### 診断

往路系統と復路系統は内容がほぼ同一 (類似度1.0が複数) のため、M9 の
best-match 間引き (朝日町の廊下連鎖対策) がタイの中で両方の旧 family を
同一の新 family に寄せ、**もう片方の新 family が成分に入り損ねて新設に
落ちる**。20系は成分こそ 2:2 だがページ割付 (old_page 写像) が同様に偏り、
旧2 family 分の便が片方のページに乗る。former_names は成分単位で付与される
ため「新設なのに旧名称」という矛盾表示が生じる。

### 一般化 (提案 — 2026-07-28 副作用調査で改訂)

**当初案「最適割当 (1:1) への置換」は撤回**: M9 の成分は N:M が正当
(朝日町の 21→9 統合 = MERGED は多:1 が正解) であり、1:1 を強制すると
正当な統合を壊す。コード精読の結果、欠陥はもっと狭い:
**タイブレークが2箇所とも「confidence 同点 → 新 family 名の辞書順」で、
同じ新 family の再利用を許す**こと (段階1間引き route_family.py と
ページ割付 builder.page_family_maps)。

改訂案: 両箇所のタイブレークを**「同点なら、まだ選ばれていない新 family を
優先 (それも同点なら辞書順)」**に変える。非同点の割付 (MERGED 等) は定義上
一切変わらないため、**影響は confidence が完全同点の成分に限定**される。

副作用の実測 (scratchpad/tie_survey.py、2026-07-28):

| ペア | 同点タイの旧family | 割付が変わる | 備考 |
|---|---|---|---|
| 朝日町 (M9基準 21→9) | **0** | **0** | MERGED 2件 (2→1, 4→1) は非同点で不変 |
| 名古屋 (M9基準 同名改称) | **0** | **0** | |
| 京都 | 2 | 1 | 20(菱川～淀) が正しく菱川ページへ。孤立解消1 |

西/特西の 2:1 潰れはページ割付でなく**段階1間引きの中のタイ**なので、
間引き側のタイブレーク変更で解消する (成分が 1:1+1:1 の RENAMED に再分解
される見込み)。実装時の回帰基準: 朝日町・名古屋・桑名・永井で成分と
ページ割付が**完全不変**であること (同点タイ0件の実測が保証)。
併せて「lev1=新設 ∧ (former_names または類似度1.0 candidate)」の矛盾を
self_check に採録する。

**実装結果 (2026-07-28、同点証拠階層 = 向き→名称類似→未使用→辞書順)**:
before/after の identity ダンプ照合で、朝日町・名古屋・桑名・臨港は
**成分・ページ割付とも完全不変**。京都のみ変化 — merged 2:1 ×2 が
**正しい組の renamed 1:1 ×4** (特西4↔特西4、西3↔西3、西2↔西2、西4↔西4 —
交差なし) に再分解され、ページ割付3件 (西3・西4・20菱川) が正常化。
矛盾検知 `level1_with_counterpart` を self_check + 検証モードに常設。

## 2. G2 — ④の対表示がページ/セル割付を跨ぐ (指摘 3.1, 3.8, 3.12)

### 観測

京都の self_check 8件は**全部この不整合**である (検証モード常設化が
初の実戦で機能した):

```
市バス106     irregular@1 ヘッダ 10→5  / ④ 5→5
市バス20(南横大路→淀) weekday ヘッダ 36→15 / ④ 26→15   (土日祝も同様)
市バス20(菱川→淀)     weekday ヘッダ 0→11  / ④ 10→11  (新設ページに旧列が出る)
市バス臨      irregular@1 ヘッダ 44→38 / ④ 38→38 (mixed)
```

106 の実態はデータエラーではなく**エンコーディングの変更**だった:
旧は祇園祭週末を1 service (10便・9日) で、新は前祭/後祭・系統別に
4 service (計15便、7日+2日の2世界) で書いている。便対応はセル割付と
無関係に旧便を両世界の新便へ対応させるため、ヘッダ (割付: 10→5 / 0→10) と
④ (対: 5→5 / 旧時刻が②側にも見える) が食い違う。立川と同じ見かけだが、
立川 (期間初日の削除漏れ = データ起因) とは原因が異なる。

### 一般化

STM 計測 (stm_measurement.md 案Y) で特定済みの「v1 対応が表示セルを
知らない」問題の国内実証。跨ぎは**ページ間** (20系・西系 — G1 の帰結) と
**セル間** (106・臨) の2形態がある。対処は:

1. G1 の修正で対応自体を正す (ページ跨ぎの大半は消える)、その上で
2. **④の列構成・件数をページ/セル割付と同じ分割に従わせる** — 跨ぎ対は
   その面では片側扱い (removed/added) にするか、割付内で再ペアリング
   する。SD5b 双子写像の拡張 (= STM 案Y)。ヘッダと④の一致は既に
   self_check の不変条件なので、修正の完了判定に使える。

## 3. G3 — 循環線の分割単位が面ごとにバラバラ (指摘 3.13〜3.20, 3.70, 3.1)

### 観測 (①=概要/地図、③=時間帯別本数、④=時刻表)

| 路線 | ① legs | ③ 行 | ④ シート |
|---|---|---|---|
| 205・202・203・204・207・北8 | loop 1本 | system 2行 (ラベルが**同一文字列**「九条車庫前→九条車庫前」) | **1枚** (左右回り混在) |
| 208 | loop 1本 (地図は**1色**) | system 2行 (同上) | **2枚** (九条近鉄前先回り / 地下鉄九条駅前先回り) |
| 206 | loop 1本 | system 2行 | **5枚** (「北大路BT先回り」「同（2）」等 — 過分割+重複ラベル) |
| 20(菱川) ラケット | — | まとまる | 2枚 (経由別) |

つまり、同じ「循環をどう分けるか」に対し、①は1本、③は2行 (ただし識別
不能なラベル)、④は1/2/5枚とばらつく。ユーザーの「状況が掴みづらい」は
この不統一そのもの。208 だけが偶然④で望ましい形になっている。

### 診断

- 方向グループ併合が loop では両回りを1 leg に畳む → 地図が1本1色、
  ④の既定が1枚。
- ③の system 行 (パターンクラスタ) は左右回りを分けているが、行ラベルが
  「起点→終点」生成のため循環では**起終点が同一になり無意味**。
- ④のシート分割 (廊下ベース) は回り方向を知らず、たまたま割れたり
  (208)、過分割したり (206)、割れなかったり (205) する。

### 一般化 (提案)

**循環線では「回り (orientation)」を第一分割とし、①地図・③・④が同じ
分割を共有する**という表示規約 (PI 候補)。orientation は停車列の巡回方向
から内容主導で決定的に判定できる (direction_id は使える場合も裏取りに
留める — 京都には両値あり)。ラベルは起点→終点でなく「◯◯先回り」
(回り方向の最初の主要停留所) を用いる — 206 の「（2）」重複ラベルも解消。
地図は分割単位ごとに線種/記号を分ける (色は補強)。

## 4. G4 — 路線ソート (指摘 3.90)

現行仕様: `(新設・廃止 → 変化あり → 変化なし)` の3ブロック、各ブロック内は
route_group 名の**単純文字列順**。このため:

- 西3(→特西4)・西4(→西2) は新設ブロックで [2][3]、対をなす
  特西4(→西3)[90]・西2(→西4)[98] は変化ブロックの「特」「西」の位置 —
  **88ページ離れる**
- 全角/半角・「特」接頭辞で番号系列が散る (20 と 特西4 の並び順が
  数字順にならない)

一般化 (提案): (a) ブロック内を**数字の自然順** (全角正規化+数値比較) に、
(b) **同一 family 成分のページは隣接させる** (成分 id を第2キーに) — 新設に
落ちたページも candidates の成分に引き寄せられ、3.2 と 3.90 が並ぶ。

## 5. 個別の解答

- **3.40 市バス58 清水道の連続停車**: 実データである。新世代で
  **stop_id 125320 → 125310 (どちらも「清水道」、172m 離れた別の乗り場) に
  連続停車する便が30便**新設されている。同名別位置の実在停留所への連続
  停車で、表示は正しい。なお両世代とも「京都駅八条口」が**同一 stop_id で
  2行連続** (距離0m、26便) という生データの癖も存在する (時間調整の
  ダミー行とみられる)。
- **3.8 市バス106**: データエラーではなく、祇園祭臨時の service 編成が
  1本→4本 (前祭/後祭×系統) に変わったもの。表示の矛盾は G2。
- **快速205**: 「市バス快速205」[78] と「快速205」[107] の2ページに割れて
  おり (route_short_name の表記ゆれ)、[78] に irregular 3→0 の old_only、
  [107] に content 94→100日のセルが分かれて出る。G1/G4 と同族の
  「名前による分断」の一例として記録。
- **explained_ratio 0.9985**: 残差が僅かにある (京都固有の調査は未実施。
  別途精査対象)。
