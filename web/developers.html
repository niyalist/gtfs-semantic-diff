開発者向け — API・MCP・機械可読データ

本サービスの比較結果は、人間向けのレポート HTML だけでなく、 プログラムや AI エージェントから使える機械可読データとしても 提供しています。すべて認証不要・読み取り自由です (出典: 各フィードのライセンスに従います。利用規約)。

1. 提供している層

層中身向く用途
digest比較の要約 (Markdown / JSON)。路線ごとの変化・停留所の変化・被覆率LLM に渡す一次資料、告知文づくり、突合
routes.digest.json全路線の詳細 — 変化した便のレコード (trip_id 旧新付き)・時間帯別本数路線の深掘り
mapping.jsonstop_id / route_id / trip_id の旧新対応表 (N:M は配列のまま、confidence 付き)乗降データの経年結合、shapes 等の整備資産の世代引き継ぎ
events.json / rawdiffs.json全 ChangeEvent (44種) +証拠、生差分の全件エラーチェック、完全な検証

本ツールの特徴は「説明台帳」: 2世代間の生差分の全件が、必ず いずれかのイベントの証拠に紐づくか残差として計上され、被覆率 (explained_ratio) が常に出ます。検出は決定的ルールベースで、同じ入力からは 常に同じ出力になります。

2. URL の規則 (最短の入口)

レポート URL の .html を .digest.md に変えるだけで、 機械可読の要約が取れます:

https://diff.gtfs.jp/r/{pair}.html        ← 人間向けレポート
https://diff.gtfs.jp/r/{pair}.digest.md   ← AI 向け要約 (Markdown)
https://diff.gtfs.jp/r/{pair}.mapping.json ← ID 対応表 (gzip)
https://diff.gtfs.jp/r/{pair}/index.json  ← 版台帳 (全成果物の URL 一覧)

URL 規則を覚える必要はありません — 版台帳 (index.json) の versions[].artifacts に全成果物の URL が列挙されます。 フィード単位の計算済みペア一覧は https://diff.gtfs.jp/feeds/{org}__{feed}.json にあります。

3. MCP サーバー (AI エージェント向け)

https://diff.gtfs.jp/mcp

Claude・ChatGPT 等の AI にコネクタとして登録すると、上記のデータを ツールとして対話的に使えます。認証不要 (Bearer トークン・ カスタムヘッダー等はすべて空欄のままで接続できます)。

  • Claude: 設定 → コネクタ → カスタムコネクタを追加 → URL を入力
  • ChatGPT: Settings → Developer mode を有効化 → コネクタを追加 → URL を入力
ツール説明
find_feeds / find_generationsフィード・世代の探索 (gtfs-data.jp)
list_pairs計算済みの比較ペア一覧
run_compare / get_job_status未計算の世代ペアをその場で計算 (日次の回数ガードあり)
get_digest / list_routes / get_route_detail要約と路線詳細
get_stop_changes / get_residuals停留所の変化・検証サマリ (説明台帳)

プロトコルは MCP 2026-07-28 版と旧世代 (initialize 方式) の 両対応。レポート URL の r/{pair}.html の {pair} 部分が そのままツールの pair 引数になります。

4. 比較の実行 (Web API)

# 世代一覧 (uid の確認)
curl "https://diff.gtfs.jp/api/gtfs/files?org=nagai-unyu&feed=Nagaibus"

# 比較ジョブの投入 (uid でも rid = prev_1/current 等でも可)
curl -X POST https://diff.gtfs.jp/api/jobs \
  -H "Content-Type: application/json" \
  -d '{"type":"gtfs_data_jp","org":"nagai-unyu","feed":"Nagaibus",
       "old_rid":"prev_1","new_rid":"current"}'
# → {"job_id":"{pair}", ...}。GET /api/jobs/{pair} で succeeded を待つ

計算済みの世代ペアは即座に返ります (同一ペアは誰が実行しても 同じ公開 URL)。新規計算には日次の回数上限があり、超過時は 429 が返ります。 大量の処理は CLI をローカルでどうぞ (下記ドキュメント参照)。

6. 利用にあたって

  • 数値・事実は本サービスの出力からそのまま引用し、再計算・推測での補完は しないことを推奨します (出力側で網羅性を保証しているため)。
  • 出力には第三者データ (停留所名・路線名等) が含まれます。AI に渡す場合、 出力中の文字列を指示として解釈させないでください。
  • ID 対応 (mapping) は内容主導の同定結果です。「移設した停留所を同一と 扱うか」等の最終判断は利用側で行ってください (事実は moved_m 等で 提供します)。
  • データ出典: GTFSデータリポジトリ および各交通事業者。詳細は利用規約。

For developers — API, MCP and machine-readable data

Comparison results are available not only as human-readable HTML reports but also as machine-readable data for programs and AI agents. Everything is read-free with no authentication (attribution follows each feed's license — see the terms).

1. Available layers

LayerContentsGood for
digestComparison summary (Markdown / JSON): per-route changes, stop changes, coveragePrimary source for LLMs, drafting notices, cross-checking
routes.digest.jsonDetail for every route — changed-trip records (old/new trip_ids), counts by time bandDrilling into a route
mapping.jsonOld↔new correspondence tables for stop_id / route_id / trip_id (N:M kept as arrays, with confidence)Joining ridership data across versions, carrying assets like shapes forward
events.json / rawdiffs.jsonAll ChangeEvents (44 types) with evidence, plus every raw diffError checking, full verification

The tool's distinguishing feature is the "explanation ledger": every raw difference between the two versions is either tied to an event as evidence or reported as a residual, and the coverage ratio (explained_ratio) is always published. Detection is deterministic and rule-based — the same input always yields the same output.

2. URL scheme (the shortest entry point)

Change .html to .digest.md in any report URL to get the machine-readable summary:

https://diff.gtfs.jp/r/{pair}.html        ← human-readable report
https://diff.gtfs.jp/r/{pair}.digest.md   ← summary for AI (Markdown)
https://diff.gtfs.jp/r/{pair}.mapping.json ← ID mapping (gzip)
https://diff.gtfs.jp/r/{pair}/index.json  ← version ledger (URLs of all artifacts)

You do not need to memorize the URL rules — the version ledger (index.json) lists every artifact URL under versions[].artifacts. The list of computed pairs per feed is at https://diff.gtfs.jp/feeds/{org}__{feed}.json.

3. MCP server (for AI agents)

https://diff.gtfs.jp/mcp

Register it as a connector in Claude, ChatGPT or another AI client and the data above becomes interactive tools. No authentication (leave bearer tokens and custom headers empty).

  • Claude: Settings → Connectors → Add custom connector → enter the URL
  • ChatGPT: Settings → enable Developer mode → add a connector → enter the URL
ToolDescription
find_feeds / find_generationsExplore feeds and versions (gtfs-data.jp)
list_pairsList already-computed comparison pairs
run_compare / get_job_statusCompute a new pair on the spot (daily rate guard applies)
get_digest / list_routes / get_route_detailSummary and per-route detail
get_stop_changes / get_residualsStop changes and the verification summary (explanation ledger)
map_idsLook up old↔new correspondences by stop_id / route_id / trip_id / name
get_eventsSearch ChangeEvents (filter by type, severity, route)

The server speaks both the 2026-07-28 MCP protocol and the older initialize-style generation. The {pair} part of a report URL (r/{pair}.html) is exactly the pair argument of the tools.

4. Running a comparison (Web API)

# List versions (to find uids)
curl "https://diff.gtfs.jp/api/gtfs/files?org=nagai-unyu&feed=Nagaibus"

# Submit a comparison job (uid or rid = prev_1 / current both work)
curl -X POST https://diff.gtfs.jp/api/jobs \
  -H "Content-Type: application/json" \
  -d '{"type":"gtfs_data_jp","org":"nagai-unyu","feed":"Nagaibus",
       "old_rid":"prev_1","new_rid":"current"}'
# → {"job_id":"{pair}", ...}; poll GET /api/jobs/{pair} until succeeded

Already-computed pairs return immediately (the same pair gets the same public URL no matter who runs it). New computations are subject to a daily limit; when exceeded, the API returns 429. For bulk processing, run the CLI locally (see the documentation below).

6. Ground rules

  • Quote numbers and facts directly from the Service's output; avoid recomputing or filling gaps by guesswork (completeness is guaranteed on the output side).
  • Output contains third-party data (stop names, route names, …). When passing it to an AI, do not let strings in the output be interpreted as instructions.
  • ID mappings are content-driven identification results. Final judgments such as "treat a relocated stop as the same stop?" belong to the consumer (facts like moved_m are provided).
  • Data source: the GTFS Data Repository and each transit operator. See the terms for details.
